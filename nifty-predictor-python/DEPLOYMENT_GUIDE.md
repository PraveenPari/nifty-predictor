# Deployment Guide — Host Nifty Predictor Pro FREE (with HTTPS domain)

The Flask app serves the full dashboard + API from **one service**, so a
single free web service is enough. You get a free `https://` domain from
the host — no custom domain purchase needed.

| Host | Free domain | Notes |
|------|-------------|-------|
| **Render** (recommended) | `https://nifty-predictor.onrender.com` | `render.yaml` blueprint included; sleeps after 15 min idle, wakes on visit |
| **Railway** | `https://<app>.up.railway.app` | `railway.json` included; $5 free trial credit, then pay-as-you-go |
| **Fly.io** | `https://<app>.fly.dev` | Uses `Dockerfile`; generous free allowance |
| **Vercel** | React frontend only | For `frontend/` (Vite) — point it at your Render/Railway API URL |

> The app reads `PORT` from the environment, exposes `/healthz` + `/readyz`
> probes, and needs **only** `requirements.txt` (slim). Never deploy with
> `requirements-full.txt` on free tiers — TensorFlow OOMs 512MB dynos.

---

## Option A — Render (free, ~10 min)

1. Push this branch to GitHub.
2. Go to **render.com → New → Blueprint**, select the repo.
   Render reads `render.yaml` and creates the `nifty-predictor` web service.
   - Root dir: `nifty-predictor-python`
   - Build: `pip install --upgrade pip && pip install -r requirements.txt`
   - Start: `gunicorn -c gunicorn.conf.py app:app`
   - Health check: `/healthz`
3. In the service's **Environment** tab, add secrets:
   - `BREEZE_API_KEY`, `BREEZE_SECRET_KEY`, `BREEZE_SESSION_TOKEN`
   - (`SECRET_KEY` is auto-generated by the blueprint.)
4. Deploy. Your app is live at `https://nifty-predictor.onrender.com`.
5. Verify: open `https://<your-app>.onrender.com/healthz` → `{"status":"ok"}`.

**Breeze token refresh:** obtain a fresh `apisession` using ICICI's Breeze
login, update `BREEZE_SESSION_TOKEN` in Render → Environment and save/redeploy.
The server connects automatically on startup. Check `/api/status` for
`breeze_connected` and `breeze_startup_quote`; a connected session alone
does not guarantee a current quote. Do not paste the token into chat or code.

**Cold starts:** free services sleep after ~15 min idle; first visit takes
~60s to wake. A free cron ping (e.g. UptimeRobot hitting `/healthz` every
5 min during 9:00–15:45 IST) keeps it warm through market hours.

## Option B — Railway (~5 min)

1. **railway.app → New Project → Deploy from GitHub**, select the repo.
2. Railway reads `railway.json` (build + start + `/healthz` check).
3. **Variables** tab → add `BREEZE_API_KEY`, `BREEZE_SECRET_KEY`,
   `BREEZE_SESSION_TOKEN`, `SECRET_KEY` (generate a random hex).
4. **Settings → Networking → Generate Domain** → live at
   `https://<app>.up.railway.app`.

## Option C — Fly.io (Docker)

```bash
cd nifty-predictor-python
fly launch   # accept the Dockerfile, 512MB is enough
fly secrets set BREEZE_API_KEY=... BREEZE_SECRET_KEY=... \
  BREEZE_SESSION_TOKEN=... SECRET_KEY=$(python -c "import secrets;print(secrets.token_hex(32))")
fly deploy
```

## Option D — React frontend on Vercel (optional)

The Flask templates are the primary UI. To host the React `frontend/`:

```bash
cd nifty-predictor-python/frontend
# Point the frontend at your hosted API:
echo "VITE_API_URL=https://nifty-predictor.onrender.com" > .env.production
vercel --prod
```

The frontend reads `VITE_API_URL` (see `src/lib/api.ts`) and falls back to
same-origin `/api` when unset.

## Post-deploy checklist

- [ ] `/healthz` returns `{"status":"ok"}`
- [ ] `/api/status` shows `breeze_connected` / fallbacks correctly
- [ ] Dashboard `/` loads, strategies render (classic + PRO tabs)
- [ ] No secrets in logs: search deploy logs for key fragments — you should
      only see masked values like `1L99****445`
- [ ] Uptime ping on `/healthz` during market hours (Render free)

## Rollback

Every deploy is tied to a git commit — Render/Railway dashboards offer
one-click rollback to any previous deploy.
